# Статус проекта для передачи

Дата сверки: 25 сентября 2026 года.

## Текущая цель

Довести «Помощник Food Fiction» от локально проверенного прототипа до эксплуатационного сервиса: подключить реальный портал Битрикс24, подтвердить корректность и полноту синхронизации корпоративных материалов, заменить общий код доступа на пользовательскую авторизацию с проверкой прав, затем добавить Hermes/языковые модели, многоязычный поиск и проверенный голосовой сценарий.

Текущий репозиторий уже содержит рабочий сервер синхронизации и пользовательский веб-интерфейс, но ещё не является готовой производственной системой. Реальные данные компании, портал Битрикс24, Hermes и серверные сервисы распознавания/синтеза речи не подключены.

## Что завершено на текущем этапе

- Реализована синхронизация явно настроенных источников Битрикс24:
  - рекурсивный обход папок Диска, пагинация и загрузка PDF через REST API;
  - чтение дерева и Markdown-текста Базы знаний 2.0 через REST 3.0;
  - периодическая сверка и запуск сверки по защищённому исходящему вебхуку.
- Реализовано безопасное обновление локальной базы:
  - SQLite-хранилище, полнотекстовый индекс FTS5 и сохраняемая между перезапусками очередь;
  - атомарная замена снимка источника только после полного успешного обхода;
  - удаление исчезнувших документов после успешной сверки;
  - блокировка поиска по ошибочным или просроченным источникам;
  - повторные попытки с задержкой и запрет одновременной работы двух процессов с одной БД.
- Реализована обработка PDF в отдельном процессе с тайм-аутом, лимитами размера/страниц/текста, сохранением номера страницы и состояниями `needs_review`, `needs_ocr`, `extraction_failed`, `file_too_large`.
- Реализована проверка версии перед публикацией: одобрение привязано к `fingerprint`, а изменение документа отменяет прежнее одобрение. Для заранее доверенных источников доступна автоматическая публикация через `require_review=false`.
- Реализован защищённый серверный API: отдельный административный bearer-токен, ограничения источников, проверка домена и токена вебхука, лимит тела вебхука, запрет следования неподтверждённым URL и фильтрация ссылок на источник.
- Реализован пользовательский веб-интерфейс Food Fiction:
  - адаптивный экран вопроса, примеры запросов, показ найденных фрагментов и исходного документа;
  - отдельный режим локального предпросмотра только с вымышленными учебными материалами;
  - вход по отдельному коду, HttpOnly/SameSite cookie, ограничение попыток и доступ только к `web_scopes`;
  - браузерная диктовка и озвучивание через Web Speech API с текстовым запасным сценарием;
  - CSP и защитные HTTP-заголовки, отсутствие административных секретов в статических ресурсах.
- Добавлены автоматические тесты синхронизации, хранилища, PDF, очереди, безопасности API и пользовательского веб-доступа.

## Ключевые технические решения

- Python 3.11+, FastAPI, `httpx`, `pypdf`; данные и лексический поиск — SQLite + FTS5.
- Диск Битрикс24 используется для PDF, База знаний 2.0 — для Markdown-статей. Вложения статей автоматически не импортируются.
- Событие Битрикса не определяет объект чтения: оно только ставит полную сверку заранее разрешённых корней в очередь. Это исключает чтение произвольного URL или источника из входящего события.
- При неполном обходе старые документы сохраняются для диагностики, но источник переводится в ошибочное состояние и исключается из поиска. Сервис работает по принципу fail closed.
- Пользовательский браузер не получает `KNOWLEDGE_API_TOKEN`; для временного веб-доступа используется отдельный код и серверная сессия в памяти процесса.
- Сейчас сервис возвращает фрагменты источников, а не сгенерированный ответ. Данные из документов считаются данными, а не инструкциями для модели.
- Диктовка и озвучивание на данном этапе зависят от возможностей и внешних сервисов браузера; сервер не хранит аудио.
- Один процесс Uvicorn на одну SQLite-базу — сознательное ограничение текущей архитектуры.

## Основные файлы этапа

Точного списка изменений относительно предыдущей версии нет: в переданном каталоге отсутствуют `.git` и журнал коммитов. Ниже перечислены основные файлы, состояние которых сверено с работающим кодом.

- `knowledge/app.py` — создание FastAPI-приложения, административный API, поиск и приём вебхуков.
- `knowledge/config.py` — валидация настроек, секреты из окружения и параметры веб-доступа.
- `knowledge/bitrix.py` — адаптер REST API Битрикс24 и безопасная загрузка файлов.
- `knowledge/sync.py` — обход источников, версии документов, извлечение PDF и фоновая очередь.
- `knowledge/store.py` — схема SQLite/FTS5, снимки источников, статусы, одобрение и поиск.
- `knowledge/pdf_extract.py`, `knowledge/lease.py` — изолированное извлечение PDF и блокировка второго процесса.
- `knowledge/web.py` — пользовательские сессии, ограничения источников и веб-API.
- `knowledge/preview.py` — локальный предпросмотр с вымышленными данными.
- `knowledge/static/index.html`, `knowledge/static/app.js`, `knowledge/static/styles.css` — интерфейс сотрудника, браузерный голос и адаптивное оформление.
- `tests/test_connector.py`, `tests/test_web.py` — 30 автоматических сценариев.
- `README.md`, `PROJECT_PLAN.md`, `PRODUCT.md`, `DESIGN.md` — эксплуатационные, продуктовые и визуальные решения; первые два файла требуют актуализации по веб-интерфейсу.

## Известные проблемы и ограничения

- Интеграция не проверена на реальном портале Битрикс24: необходимо подтвердить доступность REST 3.0, форму ответов, права сервисного пользователя, реальные события, URL скачивания и ссылки на документы.
- `README.md` и строка статуса в `PROJECT_PLAN.md` устарели: они говорят, что сайт, вход и голос ещё не подключены, хотя веб-интерфейс, вход по коду и браузерный голос уже реализованы. В README также не описаны `KNOWLEDGE_WEB_ACCESS_CODE`, `web_scopes` и `web_cookie_secure`.
- Общий код доступа, сессии и лимит попыток хранятся в памяти одного процесса. Это не замена корпоративному SSO, персональным ACL, централизованному отзыву сессий и распределённому rate limiting.
- Права конкретного сотрудника из Битрикса не переносятся. `web_scopes` — статический серверный список, общий для вошедших пользователей.
- Поиск только лексический; нет семантического поиска, перевода запроса, Hermes, основной/резервной языковой модели, формирования ответа и проверки ответа моделью.
- Голос использует Web Speech API браузера. Поддержка языков, приватность обработки и качество в шумном помещении зависят от устройства/браузера и не проверены.
- OCR отсутствует. Сканированные PDF блокируются как `needs_ocr`; сложные таблицы и порядок извлечённого текста нужно проверять по оригиналу.
- Вложения Markdown-статей не скачиваются; База знаний 1.0 не поддерживается; для статей пока нет подтверждённой ссылки на оригинал.
- Нет пользовательской панели администратора для просмотра и одобрения версий — доступны только административные HTTP-маршруты.
- Нет E2E-браузерных, accessibility-, нагрузочных и интеграционных тестов, мониторинга, резервного копирования и процедуры восстановления.

## Опробованные, но не сработавшие подходы

В доступном коде, документации и тестах нет подтверждённых записей о подходах, которые были реализованы и затем признаны неработающими. История Git отсутствует, поэтому восстанавливать такие решения по догадкам нельзя. Реальное подключение Битрикс24, Hermes и внешних голосовых сервисов ещё не выполнялось и не должно считаться неудачной попыткой.
